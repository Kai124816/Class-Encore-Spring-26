Q1)  A — Woof / Meow / ...
          Each call to make_noise(animal) calls animal.sound(). Python uses
          dynamic dispatch: the method looked up is the one belonging to the
          ACTUAL runtime type of the object. Dog.sound() returns "Woof",
          Cat.sound() returns "Meow", and the base Animal.sound() returns "...".

Q2)  B — oak 4
          Chair.__init__ calls super().__init__(material), which is
          Furniture.__init__. That call sets self.material = material.
          Because Chair.__init__ then sets self.legs = legs, both attributes
          exist on the Chair instance. No AttributeError occurs.

Q3)  C — 3 3
          Robot.count is a CLASS variable. Every __init__ does Robot.count += 1,
          which modifies the class-level variable directly. No instance variable
          named count is ever created. When r2.count is accessed, Python looks in
          r2.__dict__ first (nothing there), then finds Robot.count = 3 on the
          class. Both Robot.count and r2.count resolve to the same value: 3.

Q4)  A — CBA
          Top.hello() returns "C" + super().hello(). super() inside Top is Mid,
          so Mid.hello() runs, returning "B" + super().hello(). super() inside
          Mid is Base, so Base.hello() returns "A". Working back up:
          Mid.hello() = "B" + "A" = "BA", Top.hello() = "C" + "BA" = "CBA".

Q5)  B — True True False
          isinstance(t, Shape) is True because Triangle inherits from Polygon
          which inherits from Shape — isinstance checks the entire MRO.
          isinstance(t, Polygon) is True for the same reason.
          type(t) == Shape is False because type(t) is Triangle, not Shape.
          type() returns the exact class; isinstance() checks the full hierarchy.

Q6)  C — (4, 6)
          v1 + v2 calls v1.__add__(v2), which returns Vector(1+3, 2+4) =
          Vector(4, 6). print() calls __str__ on that new Vector, which
          returns "(4, 6)".

Q7)  C — Raises TypeError: Can't instantiate abstract class Drawable
          Python's ABC mechanism prevents direct instantiation of any class
          that still has unimplemented @abstractmethod methods. Drawable has
          draw() marked abstract and provides no concrete implementation, so
          calling Drawable() raises TypeError. Square CAN be instantiated
          because it implements draw().

Q8)  A — Item(sword)  and  [<Item name='sword'>]
          print(obj) calls str(obj), which uses __str__ → "Item(sword)".
          When an object appears inside a list, Python uses repr() to display
          each element, so [item] displays [<Item name='sword'>] using __repr__.
          __str__ and __repr__ serve different purposes: __str__ is for
          human-readable output, __repr__ is for container/debug display.

Q9)  D — 15
          recursive_sum(n) = n + recursive_sum(n-1). Expanding:
          5 + 4 + 3 + 2 + 1 + recursive_sum(0) = 5+4+3+2+1+0 = 15.
          The base case (n == 0) returns 0, terminating the recursion.

Q10) B — 21
          The tree represents (3 + 4) * (2 + 1).
          Add(Lit(3), Lit(4)).eval() = 3 + 4 = 7
          Add(Lit(2), Lit(1)).eval() = 2 + 1 = 3
          Mul(...).eval() = 7 * 3 = 21.
          Tree evaluation is purely recursive: each node evaluates its
          sub-expressions before combining them.

Q11) B — [3, 2, 1]
          mystery_ll builds the list as: mystery_ll(node.next) + [node.val].
          The recursive call runs to completion BEFORE appending the current
          value, so the deepest node (3) lands at index 0. Tracing:
          mystery_ll(Node(3, None)) = [] + [3] = [3]
          mystery_ll(Node(2, ...))  = [3] + [2] = [3, 2]
          mystery_ll(Node(1, ...))  = [3, 2] + [1] = [3, 2, 1]
          The list is reversed relative to the original order.

Q12) C — 5
          count_nodes counts every node recursively: 1 (for the current node)
          + count of the left subtree + count of the right subtree.
          The tree has nodes with values 1, 2, 3, 4, 5 — five nodes total.

Q13) A — [1, 3, 6, 8, 10, 14]
          Inorder traversal visits: left subtree → current node → right subtree.
          On a valid BST, inorder traversal always produces values in sorted
          (ascending) order. The six nodes 1, 3, 6, 8, 10, 14 are visited in
          exactly that order.

Q14) D — uses float('-inf') as the base case.
          A: max(node.val, None) raises TypeError when node.next is None.
          B: crashes with AttributeError if the original call passes an empty
             list (node is None → node.next raises AttributeError).
          C: returns 0 for an empty tail, which is wrong for lists containing
             only negative values (e.g., max of [-5, -3] would wrongly return 0).
          D: float('-inf') is always smaller than any real integer, so
             max(any_val, -inf) = any_val, which is correct in every case.

Q15) C — 3
          count_files recurses into Directories and returns 1 for each File.
          notes.txt (1) + a.jpg (1) + b.jpg (1) = 3. The empty docs/ directory
          contributes 0. FileSys and DirSys act as a polymorphic N-ary tree.

Q16) C — 13
          Reading MSB to LSB: 1*8 + 1*4 + 0*2 + 1*1 = 8 + 4 + 0 + 1 = 13.

Q17) D — -2
          The sign bit (leftmost) is 1, so this is a negative number.
          Two's complement negation: flip all bits → 0001, then add 1 → 0010.
          0010 = 2, so the original value is -2.

Q18) D — 1000
          0111 is 7 and 0001 is 1. 7 + 1 = 8. 8 in 4-bit binary is 1000.
          Note the carry ripples all the way to a new bit position:
          1+1=10, carry propagates: 011+001 column by column → 1000.

Q19) A — 20
          Left-shifting by k positions multiplies the value by 2^k.
          5 << 2 = 5 * 4 = 20. In bit terms, [0,1,0,1] shifted left by 2
          produces 010100 (ignoring fixed width), which equals 20 in decimal.

Q20) B — 1110
          Bitwise OR: each bit is 1 if EITHER input bit is 1.
          1010
          0110
          ----  OR
          1110

Q21) A — 1101
          Bitwise XOR: each bit is 1 if the two input bits DIFFER.
          1011
          0110
          ----  XOR
          1101

Q22) A — A / B
          A Queue follows FIFO (First-In, First-Out). Items are enqueued at
          the back and dequeued from the front. "A" was enqueued first, so
          the first dequeue returns "A"; the second returns "B".

Q23) D — 3
          list_depth([1, [2, [3]], 4]):
            depth(1) = 0  (not a list)
            depth([2, [3]]) = 1 + max(depth(2), depth([3]))
                            = 1 + max(0, 1 + max(depth(3)))
                            = 1 + max(0, 1 + 0) = 1 + 1 = 2
            depth(4) = 0
          Result = 1 + max(0, 2, 0) = 1 + 2 = 3.

Q24) D — 3
          count_ints counts integer values at any nesting level.
          "a": 1   → 1 int
          "b": {"c": 2, "d": {"e": 3}}  → recurse:
               "c": 2 → 1 int; "d": {"e": 3} → recurse: "e": 3 → 1 int
               subtotal = 2 ints
          "f": "hello" → not int, not dict → 0
          Total = 1 + 2 + 0 = 3.

Q25) B — O(log n)
          In a balanced BST each comparison eliminates half the remaining
          nodes, so search depth equals the tree height ≈ log₂(n). This is
          the same intuition as binary search on a sorted array.

Q26) D — [10, 5, 3, 7, 15]
          Preorder visits: ROOT → left subtree → right subtree.
          Visit 10, then recurse left: visit 5, then recurse left: visit 3
          (leaf), then recurse right: visit 7 (leaf). Back up, recurse right
          from 10: visit 15 (leaf). Result: [10, 5, 3, 7, 15].

Q27) A — For every node, ALL values in its left subtree are smaller than
          the node's value, and ALL values in its right subtree are larger.
          Option B only compares a node's direct children, not the entire
          subtrees — that is NOT sufficient. Option C describes a complete or
          perfect tree, not a BST. Option D describes an insertion order, not
          a structural property. The BST invariant must hold for EVERY node
          relative to ALL descendants, not just immediate children.

Q28) B — 6
          Right-shifting by 1 is integer division by 2: 12 // 2 = 6.
          In MSB-first bit representation, every bit shifts one position to
          the right (toward the LSB), and the MSB is filled with 0 for an
          unsigned number.

Q29) C — bits[0] == 1
          In MSB-first storage the leftmost bit (index 0) is the most
          significant bit, which serves as the sign bit in two's complement.
          A 1 in that position indicates the number is negative; 0 indicates
          non-negative. bits[-1] is the LSB (least significant bit) and has
          nothing to do with the sign.

Q30) C — O(n)
          In the worst case (e.g., inserting already-sorted values 1, 2, 3, …),
          the BST degenerates into a linked list where every new value is
          inserted at the rightmost leaf. Inserting the nth value requires
          traversing all n−1 existing nodes, giving O(n) per insert and
          O(n²) to build the whole tree. A balanced BST guarantees O(log n)
          but an unbalanced one does not.
